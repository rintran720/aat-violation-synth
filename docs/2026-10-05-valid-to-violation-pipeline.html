Valid-to-Violation Pipeline

synth/valid_to_violation.py turns one real, valid CCTV frame (a forklift carrying one loaded LSP) into one two-LSP violation: a second, equal LSP placed in front of the loaded one, then one cargo on that new sheet. Every image-model edit is composited back onto the original and must pass code gates (geometry, integrity) and a scored visual review before it is kept. A failed gate never publishes.

python -m synth.valid_to_violation <valid frame>
    [--reference-map work/catalogue3d/reference_maps/<stem>/reference_map.json]
    [--contact-edge x1,y1,x2,y2] [--camera work/camera.json] [--calibration work/calibration.json] [--moge]

0 · Setup

Pre-flight checks

  • Input exists, --max-attempts ≥ 1, output path does not exist yet.
  • --editor codex (default): the Codex CLI must be on PATH. --editor api: also needs the imagegen CLI and OPENAI_API_KEY.
  • Work directory: work/out/<output stem>_vision_<UTC timestamp>/.

Appearance references

One image each for forklift, LSP, SKID, cargo:

  • Default: Step A crops from work/refs/index.json, best score × √area; for LSP, prefer single thin sheets (aspect ≥ 2.5, area ≥ 5000 px).
  • --reference-map: view-matched catalogue renders (e.g. from synth.catalogue_reference_map). Its optional cargo size_m drives the 3D cargo box.

References are appearance only: the prompt states they are not to scale and their viewpoint must not be copied.

Geometry

  1. SAM3 masks of the source for forklift, LSP, cargo, floor (cached in work/vision_cache/sam3).
  2. Anchor edge: source_edge() finds the central loaded LSP (by cargo overlap) and measures the front edge of its top face on the photo. --contact-edge overrides it.
  3. Optional MoGe (--moge): records a floor-plane diagnostic in the report; not a gate.
  4. Projection (make_geometry_guide): unproject both edge endpoints onto the plane z = lsp_thickness_m using the pinhole camera from camera.json; offset them by the calibrated sheet depth (lsp_measured_size_m[1]) along the edge normal, on the side toward the camera; project back. This gives the new sheet's top polygon, sharing the edge with the original.
  5. Width sanity check: the measured edge must be within ±25 % of the calibrated width (lsp_measured_size_m[0]), otherwise the run stops and asks for --contact-edge.
  6. Outputs: geometry_guide.png (green shared edge, orange new-sheet outline) and geometry.json (pixel polygon plus the new sheet's world corners, used for the cargo box).
  7. Protected masks: union of the source's forklift, cargo and LSP masks. The composite never changes these pixels.

One attempt (both stages)

1 · Editguided_edit sends ≤ 5 images and a prompt (with last failures) to Astra + imagegen or the image API. Raw result: *_raw_NN.png.
2 · Compositepreserve_outside blends the raw edit into the base only inside a feathered rectangle around the polygon, colour-matched on the feather ring; protected objects keep exact pixels.
3 · SegmentSAM3 on the candidate for LSP, cargo.
4 · Code gatesShape, drift, guide marks, integrity and stage-specific mask checks.
5 · Visual reviewAstra scores a before/after close-up (zoom_pair); code decides from the scores.

An attempt is accepted only when every code gate and the visual gate pass. Otherwise all failure texts become "Fix these failures: …" in the next prompt. --reuse-sheet / --reuse-cargo re-verify an existing candidate (attempt 0) instead of generating one; raw-output checks are skipped for them.

Cargo target box

  • 3D projection (when the reference map gives cargo size_m): a box of that size centred on the new sheet's top face, its 8 corners projected with the camera → image bbox.
  • Fallback: scale the original load's bbox (width × 0.9, height × 1.05), standing near the new sheet's near edge and centred on the polygon.
  • Minimum accepted cargo height = 70 % of the box height.

Outputs

Next to the output

  • <input stem>_violation.png (or --output): only on acceptance, resized to the source size.
  • <output stem>_summary.png: always. Input left, output (or last candidate, marked NOT ACCEPTED) right; below: result, model calls by purpose, attempts per stage, last scores and failures, references, run time.

In the work directory

  • report.json: input hash, anchor, geometry, references, every attempt's checks, scores and failures, call counts, result, error.
  • geometry_guide.png, geometry.json
  • sheet_raw_NN.png, sheet_NN.png, cargo_raw_NN.png, cargo_NN.png, zooms, prompts, Astra responses and logs.

Exit codes

  • 0: accepted and published.
  • 1: error (bad input, missing tool, failed command, implausible edge width, …).
  • 2: ran to completion but no candidate passed in a stage.
