# cam01 — first 3D asset build

Built locally on 2026-09-29 using the supplied SAM3 crop library and existing MoGe calibration. This implements the asset-building part of Phase 1, item 3 in the project plan. No segmentation/calibration inference was rerun. No source images were sent to an external service. No synthetic training images, scenario generation, or compositing were run.

## Outputs

- `work/asset_review/index.html`: self-contained local review page with references, front/rear renders, and model links.
- `work/asset_review/contact_sheet.jpg`: overview of the eight assets.
- `work/assets/*.blend`: reusable Blender assets, with textures packed into the file. Each scene contains only asset meshes; its named collection is marked as an asset.
- `work/assets/*.glb`: portable glTF binary exports. glTF uses its standard Y-up convention; Blender files use Z-up and front +Y. The provisional pallet uses its brown base colour in GLB; procedural wood grain is preserved in the Blender file only.
- `work/assets/*.json`: bounds, dimensions, source project and texture metadata.
- `work/cli/`: CLI-Anything projects for the three authoring passes and generated bpy scripts.
- `work/previews/`: blockout/detail/final renders and final rear views.
- `work/logs/`: CLI command traces and Blender execution logs.
- `work/asset_sources.json`: source selections, texture quadrilaterals, limitations and input SHA-256 hashes.
- `work/asset_review/validation.json`: results from reopening and checking all final Blender files.

## Reproduce

Use a lightweight CPU authoring environment; `setup.sh` remains the separate SAM3/MoGe CUDA setup.

```bash
uv venv --python 3.12 .venv  # only when this environment does not already exist
uv pip install --python .venv/bin/python -r requirements-assets.txt
uv pip install --python .venv/bin/python ./tools/CLI-Anything/blender/agent-harness
.venv/bin/python -m synth.asset_sources
.venv/bin/python -m synth.build_assets --pass-number 1
.venv/bin/python -m synth.build_assets --pass-number 2
.venv/bin/python -m synth.build_assets --pass-number 3
blender --background --threads 4 --python-exit-code 1 --python blender/build_lsp.py -- config.json
blender --background --threads 4 --python-exit-code 1 --python blender/validate_assets.py -- work
.venv/bin/python -m synth.asset_report
.venv/bin/python -m pytest -q tests
```

`synth.build_assets` invokes the installed CLI-Anything Click command group in process, retaining its session and logging each command. Primitives, modifiers and base materials are authored through that harness. The Blender export script supplies the precision operations the harness lacks: applying scale before bevels, surface UV coordinates, packed image textures, asset collections and final export. LSP mesh construction follows the small dedicated script described in the implementation plan. This agent authored and inspected the models directly; no additional Codex subprocess or unverified model ID was invoked.

Re-running these commands replaces generated assets and previews at the listed paths. The SAM3 masks/crops and MoGe outputs remain inputs. The selected image names and texture corners are specific to cam01 and must be reviewed before using another camera's data. Source textures are included at their real available detail; enlarging them does not create new detail.

Revision 20 applies the user's clarification that the two unwanted dark vertical bars run outside along the body, rather than inside the cabin. ## Validation and limits

- Focused tests exercise perspective rectification, degenerate quadrilateral rejection, calibrated ray/floor intersection and actual harness material/wheel transforms.
- Blender validation reopens each saved file and checks metre units, centred/floor-aligned bounds, absence of studio objects, packed textures, LSP dimensions and the forklift wheel/fork count. Front and rear PNGs and GLB exports must exist.
- The report generator verifies the source configuration and calibration/index/point-map hashes have not changed.
- The source crop sheets and three preview passes support a visual review. They do **not** constitute the plan's human realism acceptance gate.
- The forklift has no reconstructed driver. Hidden faces, mechanical dimensions, ULD corner profiles and material appearance under CCTV lighting remain approximate. ULD shapes are box-based approximations, not manufacturer CAD.
- SKID is explicitly provisional until a full, unobstructed pallet reference is supplied.
- Real LSP XY dimensions were not supplied; XY trusts the existing MoGe result. Thickness was initially inferred as 1.5 cm, then revised to the user's explicit 10 cm estimate. This remains an estimate, not a physical measurement. The distant large top-sheet outlier was not used as a texture. Three texture files do not prove three independently measured physical sheet types.
- The actual supplied camera data is 1920×1080, while the old plan mentions 960×540. The supplied `background.jpg` visibly contains forklifts, cargo and people, so it is not yet a clean plate for the later compositing stage. Neither resolution nor the input image was silently changed.
- Lighting in the preview is a neutral studio setup. It has not yet been matched to the camera scene. The next scene-building step needs proxy/alignment work and a genuine clean background before training-image acceptance.
